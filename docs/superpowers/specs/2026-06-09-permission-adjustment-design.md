# 权限调整设计

## 背景

当前系统已有 `system_admin`、`project_admin`、`project_member` 三个系统角色，并通过 `project_admins`、`project_members` 两张项目关系表控制项目范围。新的目标是去掉“项目成员”作为可分配角色，让普通用户在没有任何角色的情况下也能按 GitLab 项目成员关系查看数据，同时让项目成员关系由 GitLab 自动同步维护。

本设计采用“权限规则集中化 + GitLab 成员覆盖同步”的方案。现有“同步 GitLab 项目”功能继续作为入口，扩展为同步项目和成员关系。

## 目标

- 系统管理员可维护和查询系统内所有功能与全部项目数据。
- 项目管理员不能访问系统设置、账号管理、权限管理页面。
- 项目管理员可新增项目，可维护自己管理的项目，可查看自己作为项目管理员或项目成员的项目数据。
- `project_member` 角色不再展示、初始化或分配。
- 无角色普通用户可登录，只能查看自己或自己所在项目允许的数据，没有任何编辑权限，个人信息除外。
- 项目成员关系由 GitLab 每日自动同步和手动同步共同维护。
- 人员能效列表和团队概览允许全员可见，但人员详情按身份限制点击和接口访问。

## 非目标

- 不删除 `project_members` 表。
- 不让实时权限判断依赖 GitLab API；GitLab 结果同步到本地后再用于权限判断。
- 不在同步过程中修改已有用户密码。
- 不把普通用户设计成一个新的角色。

## 角色和项目关系

系统只保留两个有效可分配角色：

- `system_admin`：系统管理员，拥有全系统所有数据和所有操作权限。
- `project_admin`：项目管理员，表示用户至少管理一个项目，可新增项目，可管理自己作为管理员的项目。

`project_member` 角色退场：

- 前端账号页和权限管理页不再展示“项目成员”角色。
- 后端不再用 `user.has_role("project_member")` 判断数据权限。
- 历史数据库中已有 `project_member` 角色可保留兼容，但不再初始化、不再分配、不再通过 `/api/roles` 返回。
- 历史用户身上的 `project_member` 用户角色关联可在迁移中清理；`project_members` 项目成员关系继续保留，下一次 GitLab 同步会覆盖。

`project_members` 表继续保留，含义调整为“GitLab 同步得到的项目成员关系缓存”。

权限能力按以下规则判断：

- 系统管理员：所有项目可读写。
- 项目管理员：`project_admins` 中的项目可写；`project_admins ∪ project_members` 中的项目可读；可新增项目，新增后自动成为该项目管理员。
- 普通用户：无任何系统角色也可登录；`project_members` 中的项目可读；没有项目写权限；只允许维护个人信息和修改自己的密码。

## GitLab 项目及成员同步

同步入口沿用当前 `/api/projects/sync-gitlab` 和项目管理页现有同步按钮，不新增第二套主入口。按钮文案可调整为“同步 GitLab 项目及成员”。

同步流程：

1. 读取全局 GitLab URL 和 Access Token。
2. 拉取 GitLab 可访问项目。
3. 创建本地缺失项目。
4. 对所有本地匹配项目同步成员关系，包括本地已存在项目和本次新建项目。
5. 对每个项目调用 GitLab 项目成员接口，建议使用 `members/all`，包含直接成员和继承自 Group 的成员。
6. 成员拉取和用户匹配成功后，在同一事务内覆盖该项目关系。

覆盖规则：

- 清空该项目当前 `project_members`。
- 清空该项目当前非系统管理员的 `project_admins`。
- 重新写入 GitLab 当前成员关系。
- 如果某项目成员拉取失败，不清空该项目旧关系，只记录失败原因。

GitLab 角色映射：

- Owner / Maintainer：
  - 写入 `project_members`。
  - 写入 `project_admins`。
  - 追加 `project_admin` 角色。
  - 如果用户已经是 `system_admin`，不变更其系统角色，只写项目关系。
- Developer / Reporter / Guest：
  - 写入 `project_members`。
  - 不追加任何系统角色。

用户匹配和创建：

- 已存在用户优先按邮箱匹配；邮箱缺失或未匹配时按 GitLab username 兜底。
- 已存在用户不修改密码。
- 已存在用户的昵称、邮箱等非密码字段建议只在为空时补齐，避免覆盖系统内人工维护的信息。
- 不存在用户时自动创建账号。
- 新用户用户名使用 GitLab username；若冲突，追加 GitLab user id。
- 新用户邮箱、昵称来自 GitLab。
- 新用户初始密码使用系统设置中的“GitLab 同步新用户默认密码”。
- 如果默认密码未配置，则跳过自动创建该用户，并在同步结果中提示。

同步结果应返回：

- GitLab 项目总数。
- 新建项目数。
- 已存在项目数。
- 项目同步失败数。
- 新建用户数。
- 跳过用户数。
- 同步普通成员关系数。
- 同步项目管理员关系数。
- 失败项目和失败成员原因。

## 自动同步设置

系统设置页新增“GitLab 同步配置”分组：

- `gitlab_sync_enabled`：是否启用 GitLab 项目及成员自动同步。
- `gitlab_sync_schedule_time`：每日同步时间，格式 `HH:MM`。
- `gitlab_sync_default_password`：新建同步用户的初始密码，加密存储。

调度规则：

- 应用启动时，如果 `scheduler_enabled` 和 `gitlab_sync_enabled` 都开启，注册每日任务 `gitlab_project_member_sync`。
- 系统设置保存后刷新调度器，同时刷新该 GitLab 同步任务。
- 手动同步和自动同步复用同一个服务方法。
- 自动同步只处理项目、用户、`project_members`、`project_admins`、必要角色，不改已有用户密码。
- 自动同步失败只记录日志，不影响每日代码审查、Webhook、人员能效等任务。
- 自动同步结果建议写入任务日志，任务类型使用 `gitlab_sync`；若不写任务日志，也必须写入应用日志。

## 菜单和页面操作权限

系统管理员：

- 可见所有菜单。
- 项目管理可见新增、同步、编辑、测试、执行、删除等操作。
- 系统设置、账号管理、权限管理全部可见。

项目管理员：

- 不可见系统设置、账号管理、权限管理。
- 项目管理可见新增。
- 对自己管理的项目显示可写操作，可编辑、测试、执行、查看成员。
- 对自己只是项目成员的项目只读展示，不显示编辑、执行等写操作。
- 不可删除项目。

普通用户：

- 可见菜单：项目管理、审查报告、Webhook 审查、人员能效。
- 项目管理只显示自己所在项目。
- 项目表不显示复选框和操作列。
- 无项目编辑、执行、删除、成员管理权限。
- 只允许编辑个人信息和修改自己的密码。

## 权限管理和账号管理页面

权限管理页 `/roles`：

- 只展示两个有效系统角色：系统管理员、项目管理员。
- 不展示“项目成员”角色卡片、用户数、详情和权限说明。
- 角色说明调整为矩阵：
  - 系统管理员：系统设置、账号管理、权限管理、全部项目、全部报告、全部 Webhook、全部能效详情。
  - 项目管理员：新增项目、维护自己管理的项目、查看自己可读项目数据、查看全员能效列表但详情受限。
  - 普通用户不作为角色展示，只在说明区展示“无角色用户”的默认权限。
- 后端 `/api/roles` 过滤 `project_member`，避免页面误导。

账号管理页 `/users`：

- 创建和编辑用户时只保留系统管理员、项目管理员两个角色选项。
- 移除“项目成员权限”手动分配区域。
- 用户详情里可只读展示“GitLab 同步项目成员关系”和“GitLab 同步项目管理员关系”。
- 项目成员关系来源标注为 GitLab 同步，不建议在账号页手动维护。
- 项目管理员项目授权保留给系统管理员手动兜底，但 GitLab 同步到 Owner/Maintainer 时也会自动写入。

项目成员管理入口：

- 项目详情或成员弹窗可以保留查看成员列表。
- 手动添加、移除普通成员建议隐藏或禁用，并提示“项目成员由 GitLab 同步维护”。
- 系统管理员仍可手动调整项目管理员作为兜底，但下一次 GitLab 同步会按 GitLab Owner/Maintainer 覆盖非系统管理员的项目管理员关系。

## 业务数据可见性

### 项目管理

- 系统管理员：看全部项目，可维护全部项目。
- 项目管理员：看 `project_admins ∪ project_members` 里的项目；只可维护 `project_admins` 里的项目；可新增项目。
- 普通用户：看 `project_members` 里的项目；无操作列，无编辑权限。

### 审查报告

- 系统管理员：看全部报告，可删除全部报告。
- 项目管理员：看自己可读项目的全部报告；只可删除自己管理项目的报告。
- 普通用户：只看自己的报告。判断规则是邮箱优先，历史报告无邮箱时用用户名、昵称或文件名兜底。

### Webhook 审查

- 系统管理员：看全部 Webhook 审查，可删除全部记录。
- 项目管理员：看自己可读项目的全部 Webhook 审查；只可删除自己管理项目的记录。
- 普通用户：只看提交者包含自己的记录。判断规则邮箱优先；当前 Webhook 记录只有 `author` 时用用户名或昵称兜底，后续建议补充 `author_email` 字段。

### 人员能效

- 系统管理员：看全员列表和团队概览，可打开任何人的日/月详情，可补算。
- 项目管理员：看全员列表和团队概览；只能打开自己及自己可读项目成员的人员明细；点其他人时前端提示无权查看，后端返回 403。
- 普通用户：看全员列表和团队概览；只能打开自己的人员明细；点其他人时前端提示无权查看，后端返回 403。
- 补算仍只允许系统管理员。

### 任务日志

- 项目管理员：看自己可读项目的任务日志。
- 普通用户：菜单隐藏任务日志；接口仍按可读项目过滤，避免直接访问泄露。

## 身份匹配规则

“自己的数据”统一按邮箱优先判断：

- 人员能效使用 `author_email` 与当前用户 `email` 匹配。
- Webhook 审查优先使用提交者邮箱；当前历史数据只有 `author` 时，用用户名或昵称兜底。
- 审查报告优先使用报告元数据中的邮箱；历史报告没有邮箱时，用用户名、昵称或文件名兜底。

推荐后续补充：

- Webhook 审查表新增 `author_email` 字段。
- 审查报告生成时保存作者邮箱元数据，减少历史兜底误判。

## 后端设计要点

建议增加权限 helper，集中表达能力：

- `get_readable_project_ids(user, db)`：用户可读项目。
- `get_writable_project_ids(user, db)`：用户可写项目。
- `can_read_project(user, project_id, db)`。
- `can_write_project(user, project_id, db)`。
- `can_view_person_detail(user, target_email, db)`：人员能效详情权限。
- `is_self_identity(user, email_or_author)`：邮箱优先的本人判断。

所有项目、报告、Webhook、任务、能效接口使用这些 helper，不再散落判断 `is_project_member()`。

## 数据迁移

- `settings` 表新增 GitLab 同步配置字段。
- 迁移或启动初始化不再创建 `project_member` 系统角色。
- 可删除 `user_roles` 中关联到 `project_member` 的记录。
- 若保留 `roles` 表中的 `project_member` 行，也必须从 API 和页面展示中隐藏。
- 保留 `project_members` 表和已有关系，下一次 GitLab 同步覆盖。

## 测试范围

权限 helper：

- 系统管理员所有项目可读写。
- 项目管理员只对 `project_admins` 项目可写，对 `project_admins ∪ project_members` 项目可读。
- 普通用户只对 `project_members` 项目可读，无项目写权限。

项目与同步：

- 同步创建缺失项目。
- 已存在项目也会同步成员。
- Owner/Maintainer 映射为项目管理员。
- Developer/Reporter/Guest 只映射为项目成员。
- 已有系统管理员不被变更角色。
- 已有用户不改密码。
- 新用户使用系统设置默认密码。
- 未配置默认密码时跳过新用户创建并返回提示。
- 某项目成员拉取失败时不清空旧关系。

业务 API：

- 项目列表和项目编辑权限。
- 报告列表、报告内容、报告删除权限。
- Webhook 列表、统计、详情、删除权限。
- 人员能效列表全员可见。
- 人员能效日详情和月详情按规则返回 403。
- 普通用户任务日志菜单隐藏，接口按可读项目过滤。

页面：

- 项目管理员不显示系统设置、账号管理、权限管理。
- 普通用户只显示项目管理、审查报告、Webhook 审查、人员能效。
- 普通用户项目表无复选框和操作列。
- 权限管理页不展示项目成员角色。
- 账号管理页不展示项目成员角色选项和手动成员授权区。

调度：

- 启动时注册 GitLab 自动同步任务。
- 保存系统设置后刷新 GitLab 自动同步任务。
- 手动同步和自动同步调用同一服务方法。
