# 人员能效评分系统使用指南

## 问题：不同模型评分差异大

### 根本原因

1. **评分标准主观性强** - 缺乏明确的评分锚点
2. **模型理解差异** - 不同 LLM 对"好代码"的标准不同
3. **Temperature 过高** - 导致输出不稳定
4. **缺乏量化标准** - 仅凭主观判断打分

### 解决方案

我们提供了**标准化评分模板**，通过以下方式减少模型差异：

1. **明确的评分锚点** - 每个分数段有具体描述
2. **量化检查项** - 减少主观判断空间
3. **一致性约束** - 统一评分尺度

---

## 标准化评分维度（总分 100 分）

| 维度 | 分值 | 权重 | 说明 |
|------|------|------|------|
| 注释质量 | 5 分 | 低 | 注释有用性、简洁性 |
| 业务逻辑 | 30 分 | 高 | 需求覆盖、异常处理 |
| 性能优化 | 40 分 | 最高 | 算法效率、缓存策略 |
| 安全风险 | 10 分 | 中 | 漏洞防护、数据脱敏 |
| 代码架构 | 10 分 | 中 | SOLID 原则、扩展性 |
| 编码规范 | 5 分 | 低 | 命名、格式、测试 |

> **设计说明：** 日度和月度模板采用相同的权重分配，目的是保持评分尺度一致性，便于日度分数直接聚合为月度分数（算术平均）。如果权重不同，日度和月度分数将无法直接比较。

## 配置说明

### 1. 使用标准模板（推荐）

标准模板已内置在系统中，无需额外配置。系统会自动使用 `EFFICIENCY_STANDARD_TEMPLATE`。

### 2. 使用自定义模板

如果需要自定义评分标准，可以通过以下方式配置：

#### 方式一：通过 Settings API

```bash
# 更新日度评分模板
curl -X PUT "http://localhost:8000/api/settings" \
  -H "Content-Type: application/json" \
  -d '{
    "efficiency_prompt_template": "你的自定义模板内容..."
  }'

# 更新月度评分模板
curl -X PUT "http://localhost:8000/api/settings" \
  -H "Content-Type: application/json" \
  -d '{
    "efficiency_monthly_prompt_template": "你的自定义模板内容..."
  }'
```

#### 方式二：通过前端设置页面

在设置页面的"人员能效配置"部分，填写：
- `efficiency_prompt_template`: 日度评分提示词模板
- `efficiency_monthly_prompt_template`: 月度评分提示词模板

## 减少模型差异的最佳实践

### 1. 降低 Temperature

**重要说明：** 评分任务的 Temperature 已在代码中固定为 `0.0`，无需手动配置。

对于其他 LLM 调用场景（如代码审查），可在设置中调整：

```json
{
  "llm_temperature": 0.3
}
```

**建议值：**
- 评分任务：`0.0`（已固定，保证一致性）
- 代码审查：`0.7`（允许多样化表达）

### 2. 使用结构化输出

标准化模板要求 LLM 按固定格式输出，减少随意性。

### 3. 明确评分锚点

每个分数段都有具体描述，避免模型自由发挥。

### 4. 一致性检查

系统会验证：
- 总分 = 各维度分数之和
- 分数在 0-100 范围内
- 各维度分数在对应分值范围内

## 自定义模板编写指南

### 必须包含的元素

1. **角色定义**
   ```
   你是一位资深的软件开发工程师...
   ```

2. **评分维度与标准**
   ```
   ### 评分维度与标准（总分 100 分）
   | 分数 | 标准 |
   |------|------|
   | 90-100 | ... |
   | 75-89 | ... |
   ```

3. **输出格式**
   ```
   ## 评分简述
   ## 评分明细
   ## 主要工作
   ## 总分：XX 分
   ```

4. **占位符**
   - `{author_name}`: 员工姓名
   - `{top_n}`: 工作总结条目上限
   - `{year_month}`: 年月（月度模板）

### 模板示例

```python
CUSTOM_TEMPLATE = """你是一位资深的软件开发工程师...

### 评分维度与标准（总分 100 分）

#### 1. 代码质量（50 分）
| 分数 | 标准 |
|------|------|
| 41-50 | 优秀：代码质量极高 |
| 31-40 | 良好：代码质量较好 |
| 21-30 | 一般：代码质量可接受 |
| 0-20 | 待改进：代码质量差 |

#### 2. 工作效率（50 分）
| 分数 | 标准 |
|------|------|
| 41-50 | 优秀：工作效率极高 |
| 31-40 | 良好：工作效率较高 |
| 21-30 | 一般：工作效率可接受 |
| 0-20 | 待改进：工作效率低 |

### 输出格式
## 评分简述
## 评分明细
## 主要工作（不超过 {top_n} 条）
## 总分：XX 分
"""
```

## 常见问题

### Q1: 为什么同一个提交，不同模型评分差 20 分以上？

**原因：**
- 模型对评分标准的理解不同
- Temperature 设置过高
- 缺乏明确的评分锚点
- 模糊表述（如"少量"、"基本"）导致解读差异

**解决方案：**
1. 使用标准化模板（内置，已包含量化标准）
2. 评分任务 Temperature 固定为 0.0（已在代码中实现）
3. 量化标准示例：
   - "少量冗余" → "冗余/不清晰注释 ≤ 2 处"
   - "基本完整" → "遗漏 ≤ 1 处"
   - "少数边界遗漏" → "边界遗漏 ≤ 2 处"

### Q2: 如何让评分更严格？

在自定义模板中调整评分标准：

```markdown
### 评分维度与标准（总分 100 分）

#### 1. 代码质量（50 分）
| 分数 | 标准 |
|------|------|
| 45-50 | 优秀：必须满足所有检查项 |
| 35-44 | 良好：满足 90% 检查项 |
| 25-34 | 一般：满足 70% 检查项 |
| 0-24 | 待改进：满足 <70% 检查项 |
```

### Q3: 如何让评分更宽松？

调整评分标准的门槛：

```markdown
| 分数 | 标准 |
|------|------|
| 40-50 | 优秀：满足 80% 检查项 |
| 30-39 | 良好：满足 60% 检查项 |
| 20-29 | 一般：满足 40% 检查项 |
| 0-19 | 待改进：满足 <40% 检查项 |
```

### Q4: 评分结果不稳定怎么办？

1. **降低 Temperature**: `0.3` 或更低
2. **增加重试次数**: 设置 `llm_max_retries = 5`
3. **使用同一模型**: 避免混用不同模型
4. **检查模板**: 确保模板格式正确，占位符完整

## 技术实现细节

### 模板加载顺序

1. 检查 Settings 中的 `efficiency_prompt_template`
2. 如果为空，使用内置的 `EFFICIENCY_STANDARD_TEMPLATE`
3. 格式化模板，替换占位符

### 评分解析

系统使用正则表达式解析 LLM 输出：

```python
_SCORE_PATTERN = re.compile(r"总[得]?分[:：]?\s*(\d+)\s*分?")
```

支持的格式：
- `总分：85 分`
- `总分: 85 分`
- `总分85分`
- `总得分：85分`

### 错误处理

- 如果 LLM 输出无法解析，返回 `score = 0`
- 记录警告日志，便于调试
- 不影响其他字段的解析
