# 人员能效评分系统使用指南

## 问题：不同模型评分差异大

### 根本原因（经实测验证）

1. **评分本身是高方差的随机过程** - 即便 `temperature=0`，同一模型对同一提交反复评分仍会波动 8~16 分（实测 doubao 极差 8、mimo 极差 16），单次评分只是分布中的一次抽样
2. **跨次/跨模型不稳定** - 「哪个模型更严」会随抽样翻转，并非某模型系统性偏高/偏低
3. **维度判罚依赖「问题计数」** - 模型在「能找出几个问题」上分歧大，计数差异被放大成分数鸿沟
4. **解析鲁棒性** - 部分模型输出含 markdown 加粗（`**X分**`），曾导致维度解析失败、总分校验防线失效（已修复）

### 解决方案

我们提供了**标准化评分模板**，通过以下方式减少模型差异：

1. **明确的评分锚点** - 每个分数段有具体描述
2. **量化检查项** - 减少主观判断空间
3. **一致性约束** - 统一评分尺度

## 标准化评分维度（总分 100 分）

| 维度 | 分值 | 权重 | 说明 |
|------|------|------|------|
| 注释质量 | 5 分 | 低 | 注释有用性、简洁性 |
| 业务逻辑 | 30 分 | 高 | 需求覆盖、异常处理 |
| 性能优化 | 40 分 | 最高 | 算法效率、缓存策略 |
| 安全风险 | 10 分 | 中 | 漏洞防护、数据脱敏 |
| 代码架构 | 10 分 | 中 | SOLID 原则、扩展性 |
| 编码规范 | 5 分 | 低 | 命名、格式、测试 |

> **设计说明：** 日度和月度模板采用相同的权重分配，目的是保持评分尺度一致性，便于日度分数直接聚合为月度分数（算术平均）。如果权重不同，日度和月度分数将无法直接比较。

## 配置说明

### 1. 使用标准模板（推荐）

标准模板已内置在系统中，无需额外配置。系统会自动使用 `EFFICIENCY_STANDARD_TEMPLATE`。

### 2. 使用自定义模板

如果需要自定义评分标准，可以通过以下方式配置：

#### 方式一：通过 Settings API

```bash
# 更新日度评分模板
curl -X PUT "http://localhost:8000/api/settings" \
  -H "Content-Type: application/json" \
  -d '{
    "efficiency_prompt_template": "你的自定义模板内容..."
  }'

# 更新月度评分模板
curl -X PUT "http://localhost:8000/api/settings" \
  -H "Content-Type: application/json" \
  -d '{
    "efficiency_monthly_prompt_template": "你的自定义模板内容..."
  }'
```

#### 方式二：通过前端设置页面

在设置页面的"人员能效配置"部分，填写：
- `efficiency_prompt_template`: 日度评分提示词模板
- `efficiency_monthly_prompt_template`: 月度评分提示词模板

## 减少模型差异的最佳实践

### 1. 关于 Temperature（重要澄清）

评分任务的 Temperature 已在代码中固定为 `0.0`。**但实测表明 `temperature=0` 并不能保证评分稳定**——同一模型对同一提交反复评分，doubao 波动 8 分、mimo 波动 16 分。这是因为在线模型仍受 batching、数值精度等影响，`temperature=0` ≠ 确定性输出。

> 因此「降低 Temperature」**不是**稳定评分的有效手段。真正有效的是下方第 2 条：多模型/多次采样取中位数。

对于其他 LLM 调用场景（如代码审查），可在设置中调整：

```json
{
  "llm_temperature": 0.3
}
```

**建议值：**
- 评分任务：`0.0`（已固定）
- 代码审查：`0.7`（允许多样化表达）

### 2. 多模型 / 多次采样取中位数（真正有效的稳定手段）

由于单次评分方差大，应对同一提交用多个模型（或同一模型多次）评分，取**中位数**作为最终分。各模型/各次分数的极差超过阈值时，标记为「需人工复核」。这是目前唯一能可靠抑制评分噪声的方式。

### 2. 使用结构化输出

标准化模板要求 LLM 按固定格式输出，减少随意性。

### 3. 明确评分锚点

每个分数段都有具体描述，避免模型自由发挥。

### 4. 一致性检查

系统会验证：
- 总分 = 各维度分数之和
- 分数在 0-100 范围内
- 各维度分数在对应分值范围内

## 自定义模板编写指南

### 必须包含的元素

1. **角色定义**
   ```
   你是一位资深的软件开发工程师...
   ```

2. **评分维度与标准**
   ```
   ### 评分维度与标准（总分 100 分）
   | 分数 | 标准 |
   |------|------|
   | 90-100 | ... |
   | 75-89 | ... |
   ```

3. **输出格式**
   ```
   ## 评分简述
   ## 评分明细
   ## 主要工作
   ## 总分：XX 分
   ```

4. **占位符**
   - `{author_name}`: 员工姓名
   - `{top_n}`: 工作总结条目上限
   - `{year_month}`: 年月（月度模板）

### 模板示例

```python
CUSTOM_TEMPLATE = """你是一位资深的软件开发工程师...

### 评分维度与标准（总分 100 分）

#### 1. 代码质量（50 分）
| 分数 | 标准 |
|------|------|
| 41-50 | 优秀：代码质量极高 |
| 31-40 | 良好：代码质量较好 |
| 21-30 | 一般：代码质量可接受 |
| 0-20 | 待改进：代码质量差 |

#### 2. 工作效率（50 分）
| 分数 | 标准 |
|------|------|
| 41-50 | 优秀：工作效率极高 |
| 31-40 | 良好：工作效率较高 |
| 21-30 | 一般：工作效率可接受 |
| 0-20 | 待改进：工作效率低 |

### 输出格式
## 评分简述
## 评分明细
## 主要工作（不超过 {top_n} 条）
## 总分：XX 分
"""
```

## 常见问题

### Q1: 为什么同一个提交，不同模型（或同一模型重复跑）评分差 20 分以上？

**真实原因（实测验证）：**
- **评分是高方差的随机抽样**，不是「某模型更严」。`temperature=0` 下同一模型重复跑仍波动 8~16 分，跨模型比较时差异更大
- 早期「按问题计数定档」让模型在「找出几个问题」上分歧，放大分数差（业务逻辑维度已改为按严重度定档）
- 模糊表述（如「少量」「基本」）仍会叠加放大差异

**解决方案：**
1. 使用标准化模板（内置，含严重度定档 + 量化标准）
2. 业务逻辑维度改为**按严重度定档、按性质不计数**，消除「谁找得多谁分低」
3. 多模型/多次采样**取中位数**，极差超阈值标记人工复核（单次评分不可信）

### Q2: 如何让评分更严格？

在自定义模板中调整评分标准：

```markdown
### 评分维度与标准（总分 100 分）

#### 1. 代码质量（50 分）
| 分数 | 标准 |
|------|------|
| 45-50 | 优秀：必须满足所有检查项 |
| 35-44 | 良好：满足 90% 检查项 |
| 25-34 | 一般：满足 70% 检查项 |
| 0-24 | 待改进：满足 <70% 检查项 |
```

### Q3: 如何让评分更宽松？

调整评分标准的门槛：

```markdown
| 分数 | 标准 |
|------|------|
| 40-50 | 优秀：满足 80% 检查项 |
| 30-39 | 良好：满足 60% 检查项 |
| 20-29 | 一般：满足 40% 检查项 |
| 0-19 | 待改进：满足 <40% 检查项 |
```

### Q4: 评分结果不稳定怎么办？

实测结论：`temperature=0` + 同一模型 + 增加重试，**都不能**让单次评分稳定（doubao 波动 8、mimo 波动 16 分）。有效做法：

1. **多模型/多次采样取中位数** - 唯一可靠的降噪手段（已规划支持）
2. **按严重度定档** - 业务逻辑等维度已改造，减少计数分歧
3. **核对维度解析** - 系统会用各维度重算总分纠错（已修复加粗格式解析）
4. **保留 raw 落库** - 便于事后审计每次评分的完整推理（已支持）

## 技术实现细节

### 模板加载顺序

1. 检查 Settings 中的 `efficiency_prompt_template`
2. 如果为空，使用内置的 `EFFICIENCY_STANDARD_TEMPLATE`
3. 格式化模板，替换占位符

### 评分解析

系统使用正则表达式解析 LLM 输出：

```python
_SCORE_PATTERN = re.compile(r"总[得]?分[:：]?\s*(\d+)\s*分?")
```

支持的格式：
- `总分：85 分`
- `总分: 85 分`
- `总分85分`
- `总得分：85分`

### 错误处理

- 如果 LLM 输出无法解析，返回 `score = 0`
- 记录警告日志，便于调试
- 不影响其他字段的解析
